\subsubsection{Code Reviews/Inspections}
Code reviews involve a systematic examination of the source code by peers to identify errors, enforce coding standards, and improve code quality. This activity is initiated early in the project (Phase 1: Initial Code Review Setup \& Process Definition ) and continues throughout the development cycle (Phase 3: Ongoing Code Reviews ).
\begin{itemize}
    \item \textbf{Objective:} To identify defects such as logical errors, security vulnerabilities, performance bottlenecks, and deviations from established coding standards before execution. It also aims to enhance code readability and maintainability.
    \item \textbf{Methodology:}
    \begin{itemize}
        \item \textbf{Coders'} Responsibilities: Coders lead the technical reviews of their code, focusing on logic, security, efficiency, and adherence to established standards. They are also responsible for preparing their code for review.
        \item \textbf{Non-Coders'/Specification Experts' Responsibilities:} Non-coders and specification experts actively participate in code reviews, focusing on aspects such as readability, alignment with the Software Requirements Specification (SRS), understandability of comments, and alignment with user stories. Checklists may be utilized to ensure comprehensive coverage.
    \end{itemize}
\end{itemize}

\subsubsection{Walkthroughs}
Walkthroughs are a form of peer review where a developer leads the team through the code, explaining the logic and flow. This interactive session encourages discussion and collaborative problem-solving.
\begin{itemize}
    \item \textbf{Objective:} To facilitate a shared understanding of the codebase among team members, identify design flaws, and uncover defects through a collaborative inspection process.
    \item \textbf{Methodology:}
    \begin{itemize}
        \item \textbf{Coders'} Responsibilities: Coders are responsible for leading walkthroughs of their own code, explaining its design, logic, and implementation details.
        \item \textbf{Non-Coders'/Specification Experts' Responsibilities:} Non-coders and specification experts actively question and seek clarification during walkthroughs to ensure the code's implementation aligns precisely with the defined requirements.
    \end{itemize}
\end{itemize}

\subsubsection{Documentation Review}
Documentation review involves scrutinizing various project documents to ensure their clarity, consistency, completeness, and accuracy. This process is vital for maintaining high-quality project artifacts that guide development and testing efforts. This activity is performed at key stages, including initial planning (Phase 1: Documentation Review (SRS, Test Plan) ) and prior to project submission (Phase 5: Final Documentation Review ).
\begin{itemize}
    \item \textbf{Objective:} To ensure all project documentation, including the Software Requirements Specification (SRS), Test Plan, Test Cases, and the Final Report, is accurate, consistent, and provides a clear and complete understanding of the system.
    \item \textbf{Methodology:}
    \begin{itemize}
        \item \textbf{Documents Reviewed:} The primary documents subject to review include: the Software Requirements Specification (SRS), Test Plan, detailed Test Cases, and the Final Report.
        \item \textbf{Coders'} Responsibilities: Coders review documentation for technical accuracy and contribute to sections that detail technical testing efforts.
        \item \textbf{Non-Coders'/Specification Experts' Responsibilities:} Non-coders and specification experts lead the review of all project documentation for overall clarity, consistency, completeness, and accuracy. They are also responsible for driving the compilation of all test-related sections of the final report. This includes ensuring that non-functional aspects like maintainability (e.g., well-structured and modular codebase, necessary code comments ) and usability (e.g., intuitive UI, clear feedback, consistent navigation, responsive design ) are adequately addressed and consistently described across documents.
    \end{itemize}
\end{itemize}
